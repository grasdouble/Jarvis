# Bundled project-management scripts

These scripts live with the skill whose contributor operations they support. Run them from the JARVIS repository root with Node.js 24. They are trusted contributor tooling, not product runtime capabilities; never package them into the OpenCode review sandbox or run a candidate repository's copy for credentialed operations. Follow the skill's issue scope and approval gates before using write modes.

## Command entry points

| Script | Invocation and inputs | Effects and output | Failure behavior |
| --- | --- | --- | --- |
| `scripts/github/gh-app.mjs` | `node .agents/skills/jarvis-backlog/scripts/github/gh-app.mjs --verify`, `-- <gh read arguments>`, `--write -- <gh arguments>`, `--write --git-push`, `--refresh-main`, or `--dispatch-runtime-integration OPEN_PR_NUMBER EXPECTED_HEAD_SHA`. CLI arguments select ordinary repository operations; PR create requires explicit repository, base, and head. | `--verify` checks the installed App profile. Default CLI calls use a repository-scoped read token; `--write` enables the reviewed App write profile for an already authorized action. Push mode publishes the current non-default issue branch. `--refresh-main` safely fast-forwards clean local main when eligible. The dedicated runtime dispatch mode preflights exact open PR/head and directly dispatches only the fixed workflow on main with a minimal repository-scoped token; it does not invoke `gh`. | Invalid arguments fail before use. Main refresh safely skips when unsafe. Dispatch denial/ambiguous transport is never replayed; reconcile Actions state before any authorized retry. Other GitHub, authentication, scope, and push failures return nonzero; never fall back to the owner's token or SSH identity. Short-lived tokens are revoked where possible. Actions write remains repository-wide; see [App and credential details](../../../../docs/development-github-app.md) for its limitations and gates. |
| `scripts/github/sync-project-queue.mjs` | `node .agents/skills/jarvis-backlog/scripts/github/sync-project-queue.mjs [--write]`; no positional inputs. It reads the fixed JARVIS repository/project configuration. | Default mode prints a JSON preview. `--write` updates only derived Execution order ranks, then prints the resulting plan and write counts. It does not change statuses, acceptance, dependencies, or labels. | Incomplete project/API inventory, missing fields/membership, invalid dependency data, or API errors stop the refresh with a nonzero exit. Re-read current state before retrying any uncertain write. |
| `scripts/github/sync-pr-project-metadata.mjs` | `node .agents/skills/jarvis-backlog/scripts/github/sync-pr-project-metadata.mjs [--pr NUMBER | --roadmap [--issue NUMBER]] [--write] [--ci]`. `--pr` scopes PR Issue/milestone reconciliation; `--roadmap` scopes actual-date synchronization; omit `--issue` only for explicitly authorized project-wide maintenance. `--ci` is for the trusted activated workflow context. | Default mode is a JSON preview. `--write` applies only the derived project membership/Issue/milestone or actual-date effects allowed by the selected mode. It does not alter status, labels, links, planned dates, or acceptance. | Invalid combinations, unsafe CI context, incomplete/malformed API data, ambiguity, or errors stop with nonzero status and structured safe diagnostics. Resolve the source ambiguity or reread state before retrying; never use CI mode as a local credential fallback. |
| `scripts/github/check-issue-milestones.mjs` | `node .agents/skills/jarvis-backlog/scripts/github/check-issue-milestones.mjs INVENTORY.json`; input is the complete REST `state=all` issue inventory collected with `gh api --paginate --slurp`. | Read-only. Prints one canonical issue URL per issue without a native milestone, or a success message when none are missing. It excludes valid PR records and does not print API titles or payloads. | Exit `0`: all supplied issues have milestones. Exit `1`: one or more are missing. Exit `2`: usage or inventory is invalid. Completeness of the fetched pages is the caller's responsibility. |
| `scripts/github/check-coordination-parent.mjs` | `node .agents/skills/jarvis-backlog/scripts/github/check-coordination-parent.mjs ISSUE_NUMBER`; fixed to `grasdouble/Jarvis`, reads the selected issue, native parent relationship, parent issue, every native sub-issue page, and the parent's complete comment inventory through the sibling reviewed `gh-app.mjs` helper. | Read-only/on-demand. Prints one sanitized structural decision (`eligible_to_close`, `not_eligible`, `no_parent`, or `unable_to_assess`) with issue/parent numbers, stable reason, and relevant counts. `eligible_to_close` requires every child to be `CLOSED` / `COMPLETED`, at least one valid App-authored delivery snapshot per child, and one App-authored final report matching every exact current criterion as validated. Child-mapped PR/check evidence in the final report must match a validated snapshot; conflicting PR-to-child mappings fail closed. Checklist checkbox state is not used. This is not semantic acceptance evidence. It never closes or edits issues. | Exit `0`: read completed and a decision was returned. Exit `2`: invalid/unavailable data or usage; no issue is changed. A user-authorized close is a separate skill-directed App write after a fresh eligible result, followed by state verification. There is no event listener or CI invocation. |
| `scripts/github/coordination-parent-acceptance.mjs` | `node .agents/skills/jarvis-backlog/scripts/github/coordination-parent-acceptance.mjs ISSUE_NUMBER ASSESSMENT.json [--write]`; input schema and example are in [parent acceptance assessment](parent-acceptance-assessment.md). | Default is a read-only preview. It reads the parent, complete direct-child inventory, and paginated comments; checks criterion text/outcome mappings, child coverage, evidence shape, PR-to-child mappings, current-head checks, and integration-run evidence. The caller must independently inspect every cited source and substantiate the outcome. With explicit user authorization, `--write` appends an idempotent content-addressed delivery snapshot for every completed child, including a structured incomplete record when required evidence is absent/insufficient. Later evidence can be appended as a new snapshot; prior comments are never edited. It stops before final assessment while any native child is open or any completed child's current snapshot is incomplete. Once every child has a validated snapshot and every exact criterion validates, it appends one structured final assessment. Otherwise it reports gaps without a final comment. It never edits parent body/checklist, closes the issue, or changes project metadata. Conflicting/duplicate markers or global PR-to-child mappings fail closed; after an uncertain write, reread comments before retrying. | Exit `0`: valid preview or comment operation completed (including a waiting/incomplete assessment). Exit `2`: invalid/missing input, incomplete or ambiguous data, or unavailable API; no automatic retry. A write failure with uncertain outcome requires rereading the complete comment inventory before retrying. Use only from a reviewed trusted checkout for credentialed writes. |

The adjacent `*-api.mjs`, `*-sync.mjs`, and `project-queue.mjs` modules provide tested validation, planning and adapter logic imported by those entry points; they are not separate commands. The queue compares canonical two-digit product indices and historical unpadded aliases by numeric phase, preserving dependencies and readiness; arbitrary extra leading zeroes are not a phase format. Their tests use fixtures and sanitized data.

## Local checks

```bash
node --test .agents/skills/jarvis-backlog/scripts/github/*.test.mjs
```

This runs offline behavior tests. Fixtures use synthetic keys and data; repository CI never receives the development App key.

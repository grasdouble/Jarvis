# Per-attempt LLM gateway prototype

This package contains a bounded HTTP-to-provider gateway core intended to listen on a per-attempt Unix socket, plus a fetch transport restricted to the corresponding fixed loopback API route. It authenticates the per-attempt capability, pins the provider URL/model in trusted startup configuration, rejects redirects, bounds request/response sizes, output tokens, request count and deadline, and streams response chunks with backpressure. The provider key is read from a file at startup; it is never accepted from an agent request or logged.

Run its unit suite with `pnpm --filter @jarvis/llm-gateway test`.

## Qualification limits

The Colima harness in `infra/opencode-prototype/` builds pinned ARM64 OpenCode and synthetic-gateway images, runs them as isolated containers, and qualifies the HTTP-to-Unix-socket path, OpenCode v2 session flow, fixture response, cancellation, read-only snapshot/config, writable isolated state, and cleanup when explicitly run. Its fixed relay contract now checks trusted profile/model identity and maps the bounded plan/dev mode to fixed OpenCode agents, but the prototype image and synthetic harness do not establish production image integration or qualify provider egress. The harness uses only named guest volumes and synthetic values; it does not use production Compose, private code, a real provider key, or a billable provider call. The host test runner may use a different Node version; the actual prototype images run Node 24.22.0.

This is not a production profile. The synthetic model's attempted `shell` tool is refused because the sandbox configuration does not expose that tool, and no sentinel is written; this is not a substitute for all permission-policy scenarios. The gateway does not pin resolved provider addresses against DNS rebinding, or implement durable F09 usage accounting, token counting, concurrency sharing, or cancellation/reconciliation across a manager restart. Do not mount a real key or send private repository data through this prototype.

The trusted provider catalog supports only owner-selected Copilot (`github-copilot`) and OpenAI (`openai`) profiles. Its synthetic fixtures establish profile/model binding, stream/output bounds and no automatic second-provider dispatch only. The explicit owner D02/D05 decisions do not qualify provider access or authorize live data transfer: product dispatch remains disabled until the required per-attempt egress and pinned Colima/Lima network-path qualifications pass. No live provider, credentials, private code or billing calls are used.
The `@jarvis/llm` package provides the closed owner-selected Copilot/OpenAI catalog, the shared untrusted plan/dev result envelope, and a conservative estimator for exact prepared message payloads; it does not expose a direct provider client. The worker carries the trusted mode/profile through the fixed sandbox-manager relay to an immutable OpenCode profile configuration and the per-attempt gateway config. Plan output is checked by the existing snapshot-bound validator; dev output remains untrusted text. The gateway derives provider and model from the same serialized selected profile and rejects prepared-message plus output budgets over its context window before reaching the filter; no caller-declared token count is trusted. Tests use synthetic fixtures only and do not establish live provider qualification, actual product queue composition, or exact tokenizer behavior.
